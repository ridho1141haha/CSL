## 2024-05-18 - Typewriter Effect React Render Thrashing
**Learning:** `requestAnimationFrame` loops in React components can easily cause render thrashing if they trigger state updates (`setState`) unconditionally. In `DialogueUI.tsx`, the typewriter effect updated state and checked audio logic on *every* frame, even when the calculated character index hadn't changed. Furthermore, missing dependency arrays on event listener `useEffect` hooks compound the issue by rebinding DOM events 60 times a second during these rapid renders.
**Action:** When implementing frame-based animations or continuous loops (like `requestAnimationFrame`) in React, always track the last computed value (e.g., using a local variable inside the effect or a `useRef`) and only trigger `setState` when the value actually changes. Use the `useRef` pattern (often called `useLatest`) to maintain access to fresh state in event listeners without needing to rebind them on every render.
